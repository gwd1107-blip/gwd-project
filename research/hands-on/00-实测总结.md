## 二、⚠ 必核项裁决表

此前调研标注的存疑/矛盾项，逐项裁决如下（✅证实 ｜ ❌推翻 ｜ ⛔云版无此功能 ｜ ❓仍无法确认）：

| # | 存疑项（调研口径） | 裁决 | 实测结论 |
|---|---|---|---|
| 1 | SLA 升级级数："响应 1 级+解决 4 级" vs "各 4 级"两说矛盾 | ✅裁决 | **响应升级仅 1 级，解决升级 4 级**（DOM 元素 id 实锤：fresc×1，esc1–esc4×4）。"各 4 级"资料错误 |
| 2 | KEDB 是否对终端用户门户开放 | ✅证实 | **不开放**。门户可配置模块仅公告/解决方案/请求模板/请求四项，无"问题/已知错误"。KEDB 仅供技术员内部使用，门户化差异化空档成立 |
| 3 | 服务请求能否通过邮件创建（MSP 文档称不能） | ✅证实 | **不能**。旗舰 Enterprise 云版同样成立：内置邮箱只"自动转为（事件）工单"，邮件解析命令仅能赋值请求字段，无"按服务模板创建"选项 |
| 4 | Due By Time 上限 100 天 | ❌**推翻** | 解决时限填 **101 天保存成功**，客户端与服务端均无拦截。实际上限（365/999？）未继续探测 |
| 5 | OLA："每 SLA 最多 5 OLA × 每 OLA 5 组" | ⛔云版无 | 三处交叉验证（SLA 表单全文、设置中心搜索、forwardTo=ola 直访）均无 OLA。**云版 SLA 体系不存在独立 OLA 配置**，5×5 口径在云版无法验证（疑为本地版能力） |
| 6 | 报表四层之 SQL Query Report | ⛔云版无 | 自定义报表向导仅**表格/矩阵/概要/扫描 4 种类型**，无 SQL/查询报表入口。**SQL 报表为云版阉割点**（本地版有） |
| 7 | LLM 提供商：Zia/ChatGPT/Azure OpenAI 三选、可自带 key | ❌**推翻** | 中国区仅 2 个提供商：**Zia-zlabs-qwen35-35B-v1（Zoho 托管通义千问 Qwen3.5-35B，默认）+ DeepSeek（当前"禁用"徽标不可选）**。无 ChatGPT/Azure OpenAI，**无 BYOK 输入项**。每个 GenAI 功能可独立选择 AI 提供者 |
| 8 | 服务请求审批级数："最多 5 级" vs "20 级" | ✅裁决 | 模板级审批连续添加至**第 5 级后按钮消失，上限 5 级**。"20 级"在请求模块无对应机制（疑为变更/采购模块或旧版口径） |
| 9 | 变更类型："Standard/Normal/Emergency" | ❌**推翻** | 内置 **4 类：Major / Minor / Significant / Standard，无 Normal、无 Emergency**；紧急变更以"Emergency 模板+独立工作流"形式存在 |
| 10 | 变更状态机："6 阶段扩 8 阶段" | ❌**修正** | 云版默认即 **8 阶段**：Submission→Planning→CAB Evaluation→Implementation→UAT→Release→Review→Close |
| 11 | 发布默认 9 阶段、上限 12 | ✅部分证实 | 默认 **9 阶段**（Submission/Planning/Development/Testing/UAT/Deployment/Training/Review/Closure）确认；可新建与重排序，**12 上限未实测** |
| 12 | 变更 5 种审批通过条件 | ✅证实 | 全部核实：任意人可批准 / 每个人需批准 / 首次响应动作 / 多数批准 / % 批准 |
| 13 | CAB/ECAB 多委员会 | ✅部分证实 | 可建任意多个 CAB（仅 名/描述/成员 3 字段）；**无独立 ECAB 类型**，紧急委员会靠再建 CAB 实现；**审批提醒定时器未发现** |
| 14 | 服务 SLA 绑定服务模板、表单顶部显示、请求人自选 SLA | ⛔云版无 | 云版仅"帮助台-服务级别协议"（新建表单标题即"新建事故SLA"），服务模板无 SLA 页签，服务请求表单无 SLA 字段（疑为本地版口径） |
| 15 | 服务目录"两级大类+Service Category+Service Item"四层结构 | ❌**推翻** | 实为**服务类别→服务模板两级**（类别内可挂子目录），默认 6 个类别；门户三布局（面板/卡片/列表）✅与资料一致 |
| 16 | 服务模板自定义字段配额 24 文本/8 日期/8 数值 | ❓无法确认 | 云版拖拽设计器无任何配额提示（可用字段类型 19 种），未能触发上限。该配额应为本版附加字段口径 |
| 17 | Field & Form Rules 三触发点 + 15+ 动作 | ✅证实（超出） | 触发点 3 个（On Load/On Change/On Submit）；**动作实测 20 种** |
| 18 | 事件默认状态清单与关闭代码 | ✅证实 | 默认仅 **5 状态**（Open/On Hold/Resolved/Closed/Canceled，Resolved=待请求人确认）；关闭代码内置 **7 个**（Cancelled/Failed/Moved/Postponed/Rejected/Success/Unable to Reproduce） |
| 19 | 工作流节点含独立 Approval Level / User Defined Action | ❌**推翻** | 画布共 **13 种节点**，审批内嵌于状态节点，自定义动作由自定义函数/Webhook/计时器承担，**无独立审批级与 UDA 节点** |
| 20 | 业务规则=写入时同步 pre-hook | ❌**推翻（云版）** | 云版业务规则执行时点仅**创建后/编辑后/被删除**三种，UI 无 pre-hook 选项；v15200 的 Imported 事件未找到 |
| 21 | Timer Actions（延时补偿） | ✅证实（形态差异） | 云版名为「**计划**」：定时调度 Deluge 自定义函数的 Scheduler 形态，非本地版"对请求定时执行规则动作"页面 |
| 22 | Zia MCP Tools 逐项授权清单 | ⛔未找到 | 中国区云版全设置菜单（约 110 入口）无 MCP/工具授权界面；Zia 动作面=预置快捷动作+对话内交互卡片。疑仅全球版/更新构建提供 |
| 23 | 云版资产发现能力 | ✅证实（口径修正） | 云版发现=**下载式探针（无代理凭证扫描）+凭证库+域扫描+网络扫描+SCCM 集成**；"Agent 差异化扫描 12 分钟增量"是 Endpoint Central 侧能力，SDP 云版不内置 UEM Agent |
| 24 | 折旧 4 种方法 | ❓部分 | 折旧**按产品配置**且**仅 Asset 类产品可配（耗材按钮置灰）**——后一点为实测新发现；4 种方法名称因无 Asset 类演示数据未捕获 |
| 25 | GenAI 功能中国区可用性 | ✅证实 | **9 个 GenAI 功能卡片全部存在且开关可打开**（回复协助/对话摘要/工作流协助/文本助手/检查列表生成器/自定义脚本生成器/解决方案生成/解决方法协助/请求自动审批），提供商为 Zia(Qwen)+DeepSeek |
| 26 | ESM 多实例（上限 15、模板化拉起） | ✅证实（上限未验） | ESM 目录、新实例入口、**4 种实例模板（IT/设施/财务/HR）**、统一门户、实例自治全部可用；"15 实例上限"界面未标注 |
| 27 | 冲突检测 | ✅证实（形式不同） | 以"**冻结时间窗口+维护时间窗口**"实现，非"排期重叠实时告警"式检测 |
| 28 | 工作流启用后 Closure Rules 失效边界 | ❓无法确认 | 页面无显性失效提示，本租户无启用中的工作流可观察，边界未最终裁决 |

## 三、云版 vs 本地版（On-Prem）功能差清单

以下差异均经本轮实测交叉确认（"本地版有"依据此前调研资料与官方文档口径）：

| 能力 | 本地版 | 云版（中国区实测） |
|---|---|---|
| **OLA 内部组级考核** | 有（每 SLA 5 OLA×5 组口径） | ⛔ 无 OLA 配置入口 |
| **SQL Query Report** | 有 | ⛔ 向导仅 4 种报表类型，无 SQL |
| **Zia MCP Tools 逐项授权** | v15200 资料有 | ⛔ 中国区云版未开放 |
| **Timer Actions** | 对请求定时执行规则动作 | 形态变为「计划」= 定时调度 Deluge 函数 |
| **自定义函数语言** | Deluge + Java/Node.js | 实测仅见 **Deluge** |
| **监控告警原生集成** | OpManager/Site24x7/Applications Manager 原生 | 第三方集成页未见；ManageEngine 集成页列出但侧重资产同步（默认禁用），告警转工单宜走 Zapier/Webhook |
| **Agent 增量扫描** | 有（差异化扫描 12 分钟） | 无 UEM Agent 入口，仅探针无代理扫描+集成；Agent 能力需另购 Endpoint Central |
| **服务 SLA 绑定服务模板** | 有（资料口径） | ⛔ 未见，仅统一"事故SLA" |
| **自定义字段配额 24/8/8** | 附加字段配额口径 | 云版无配额提示界面 |
| **Resource Info 资产联动题型** | 部分版本有 | 云版题型仅 4 种（是否/选择框/复选框/文本框），无资产取值题型 |
| **LLM 选择** | 全球版：Zia/ChatGPT/Azure OpenAI | 中国区：Qwen3.5-35B（托管）+DeepSeek（禁用），无 BYOK |

**自研含义**：若我们做私有化交付，OLA、SQL 报表、MCP 工具授权、多语言自定义函数、监控原生集成五项都是"云版用户拿不到"的功能，可作为对 SDP 云版直销场景的正面火力点。

## 四、中国区数据中心特有问题

1. **翻译质量缺陷（10 条实证，模块 G ⑧）**：①"简档"（应为"个人资料"）；②"Maintenance Management"整项未翻译；③"App及付费选件"生硬；④"PUBLIC"未翻译；⑤报表向导类型名与描述错位（"概要报表"描述写"一览报表…"、"扫描报表"描述写"审计报表…"）；⑥发布（Release）报表译名歧义如"已完成发布的报告"；⑦状态列显示英文 "Open"、日期显示 "Jul 22, 2026" 未本地化；⑧示例数据（服务目录分类与模板）全英文；⑨错误页全英文（404、参数错误）；⑩"技术员的可用性图表"直译、"仪表板/帮助台仪表板"混用。
2. **移动端获取受阻**：仅提供 App Store + Google Play 直链，**Play Store 国内不可达**，无国内应用市场/扫码入口。
3. **自定义域功能挂迁移警告**："ServiceDesk Plus 中对此功能的支持即将结束，请使用 Zoho Directory"——自定义域体系处于迁移过渡态；试用账号"服务URL"下拉为空（仅默认域）。
4. **商店页不可达**：store.zoho.com.cn 在测试网络下持续 Loading，版本/定价信息无法从应用内闭环获取。
5. **AI 栈国产化但封闭**：底层为 Zoho 托管 Qwen3.5-35B，DeepSeek 占位但禁用；不可换模型、不可自带 key、不可私有化——合规友好但灵活性为零。

## 五、对自研产品的启示更新

**被实测加强的差异化判断：**

1. **KEDB 门户化**：实测证实终端用户门户完全无法触达已知错误（可配置模块仅 4 项）。原"建议 5"的 KEDB 开放 + 建单前语义推荐，是**确认成立的真空地带**，可放心投入。
2. **中文体验**：从"翻译层、本土化浅"的定性判断，升级为 **10 条带截图的实证清单**（含功能项整段未翻译、描述错位等硬伤）。原生中文（含示例数据、错误页、日期格式）是低成本高感知的差异点。
3. **SQL/开放查询**：云版无 SQL 报表后，"开放查询能力（SQL 或语义查询）+ 定时推送"对报表重度用户的吸引力上升——但注意对标话术应限定"对比 SDP 云版"，本地版有此功能。
4. **OLA 组级考核**：云版缺失使原"建议 6"SLA 长板规划中的 OLA 留痕考核权重上升：私有化产品可同时打"云版没有"。
5. **审批语义**：实测确认无审批催办定时器、无 ECAB 类型——叠加催办/督办/加签/回退等中式语义，流程引擎本土化空间进一步确认。

**被实测削弱/需调整的表述：**

1. **"国产 LLM 支持不明"已不再成立——这是最重要的表述修正**。SDP 中国区已落地 Zoho 托管 Qwen3.5-35B，且 GenAI 9 项功能全开、可按功能选提供商。我们的 AI 差异化**不能再说"SDP 不支持国产模型"**，应转向四个 SDP 仍未覆盖的点：**BYOK/自带模型**（SDP 无 key 输入）、**私有化/本地模型部署**（SDP 仅托管）、**LLM 网关可插拔多模型并存**（SDP 二选一且其一禁用）、**AI 审计留痕与高风险动作人工确认**（SDP 未见对应机制）。
2. **"GenAI 完整能力仅云端"需细化**：至少中国区云端 9 项全开，不能把"AI 功能缺失"作为对云版的攻击面；攻击面在"托管不可控、不可换模型、无审计"。
3. **变更管理对标口径修正**：无 Normal/Emergency 类型、默认 8 阶段、无 ECAB——我们设计变更模块时不必照抄 ITIL 三类变更外壳，可直接以"类型自定义+模板绑定工作流"为基线（这恰是 SDP 实际做法）。
4. **Due By 无 100 天上限**：SLA 引擎时限字段不要照搬臆测的校验规则。
5. **自动化时序表述修正**："业务规则=pre-hook"在云版不成立（仅创建后/编辑后/删除后）；自研规则引擎若实现"提交前同步校验/拦截"，反而是超出 SDP 云版的能力点。
