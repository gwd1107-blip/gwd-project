# 国产/中文开源 ITSM 与服务台项目调研简报

> 导语：本简报调研腾讯蓝鲸 bk-itsm（可视化流程引擎重点分析）、其他中文开源工单/ITSM 项目（heidsoft/itsm、FeelDesk）与开源资产管理 Snipe-IT，评估国产开源生态对自研 ITSM 系统的参考价值与许可证风险。

**调研员：调研员_国产开源** ｜ 调研方式：Web 搜索 + 官方仓库/官方文档抓取 ｜ 信息时点：2026-07（以各来源页面日期为准）

---

## 一、调研范围与结论摘要

本次调研覆盖四类对象：① 腾讯蓝鲸智云 bk-itsm（重点）；② 其他中文开源工单/ITSM 项目（heidsoft/itsm、FeelDesk 等）；③ 开源资产管理 Snipe-IT；④ 作为背景补充的国际开源工单系统。

**核心结论**：国产开源 ITSM 中，bk-itsm 是唯一经过大规模企业生产验证、功能体系最接近 ITIL 全栈的开源项目，其「可视化流程引擎 + 触发器 + SLA + 服务目录」四层模型对自研产品参考价值最高，但其深度绑定蓝鲸 PaaS 体系，不可直接复用代码，应作为**产品功能设计参照系**；heidsoft/itsm 代表了 AI-Native ITSM 的最新探索方向；FeelDesk 在工单路由、SLA 计时、派单场景上有成熟设计可借鉴；Snipe-IT 则是自研产品「资产管理/CMDB 轻量版」模块的最佳功能蓝本。

## 二、腾讯蓝鲸 bk-itsm（重点调研）

### 2.1 基本信息

- **仓库**：https://github.com/TencentBlueKing/bk-itsm ，开源协议 **MIT**，隶属 TencentBlueKing 组织（蓝鲸智云开源社区）。
- **定位**：基于蓝鲸智云体系的上层 SaaS 应用「流程服务」，通过可自定义的流程模块覆盖 IT 服务管理活动（事件、问题、变更、服务请求等），源自 ITIL 方法论。
- **技术栈**：后端 Python + Django，前端 Vue，前后端分离；依赖 MySQL、Redis（从单测配置可见），权限接入 BK-IAM（蓝鲸权限中心），消息通知走蓝鲸 ESB 的 CMSI 消息管理组件。

### 2.2 与蓝鲸 PaaS 的关系（关键约束）

- bk-itsm **不是独立可部署的单体产品**，而是跑在蓝鲸 PaaS 平台上的 SaaS。社区版部署需先装蓝鲸基础包（PaaS 平台、配置平台、作业平台、权限中心、用户管理等），再以 `bk_install saas-o bk_itsm` 方式安装（来源：蓝鲸官方部署文档）。
- 它天然可调度蓝鲸体系内其他能力：配置平台（CMDB，单据可关联配置项、处理人可引用 CMDB 业务公用角色）、标准运维（bk-sops，自动化节点编排执行）、ESB（第三方 API 网关 + 消息通道）。
- 腾讯官方另授权商业衍生版（嘉为蓝鲸 ITSM），增加了动态审批、加签（前加签/后加签/加会签）、驳回路径设置、值班管理、报表服务对接等能力——这些功能**不在开源版中**，但可作为自研功能设计的参照（来源：嘉为官网 V3.5/V4.6 版本说明）。
- **对自研的含义**：bk-itsm 的代码不可剥离复用，但其产品形态证明了一个重要设计决策——ITSM 引擎应当通过开放 API/Webhook 与外部自动化平台、CMDB、IM 解耦集成，而非内置一切。

### 2.3 功能细节（依据官方产品白皮书与生态文档）

**（1）服务与服务目录**
- 概念层级：服务目录（catalogs）→ 服务项（items）→ 用户经服务项发起服务请求（service request）；支持独立服务门户（Portal）作为提单入口。
- 流程有「草稿/启用」两态，启用后才对前台生效。

**（2）流程引擎（可视化编排）**
- 节点类型：提单节点、人工/手动节点、审批节点、会签节点、自动化（API/标准运维）节点；支持并行、串行、条件分支。自动化节点支持把表单字段或自定义字符作为参数传递给外部编排，可勾选「等待结果」（工单挂起直到执行结果回传）与「异常等待」（执行异常时挂起）。
- 处理人配置来源多达 8 种：**CMDB 业务公用角色、通用角色表角色、指定个人（多人）、提单人、组织架构（接蓝鲸用户管理）、引用变量（前置节点变量实现动态处理人）、派单人指定（不预设处理人，由派单人现场指派）、不限**（仅提单环节）。
- 节点级开关：是否可转单、是否督办（提单人为默认督办人，流转中可随时督办提醒）。
- 子流程节点：多实例模式，子流程实例与父流程实例相互独立，子工单字段可**回写**父工单；支持合并工单。
- 判断节点：每条迁出路径可配条件（含对自动化执行结果的判断），可设默认迁出路径兜底。
- 表单：节点字段自定义，系统内置字段可删减；支持表单布局、字段联动、附件上传、关联配置项、保存草稿箱。

**（3）触发器（自动化规则引擎）**
- 三要素结构：触发事件 → 触发条件 → 触发动作。
- 事件类型：工单提交、工单关闭、工单废除、工单改派、工单回退、工单跳转等。
- 条件：基于内置字段的表达式（等于/大于/小于等），支持「任意满足/全部满足」。
- 动作：发送通知、修改工单字段值、**调用 RESTful 接口**（支持 GET/POST、Content-Type 配置、URL 与参数中内插变量如 `${ticket.creator.id}`、`${ticket.ticketId}`）；触发时机可选（如立即触发）。
- 另有触发记录可查，便于审计与排错。

**（4）SLA 体系**
- 分层：SLA 定义（与客户的服务协议）→ SLA 策略（按条件匹配到工单）→ SLA 统计 + **OLA 统计**（内部运营级别协议），即对外承诺与内部协同分开计时考核。

**（5）工单操作细节**
- 催办（发起人催非本人处理的单）、督办、转单、回退（支持「优先回退到处理组」）、关闭后重开（Reopen）、母子工单、查询器（自定义查询视图）、字典管理、变更目录。
- 权限：功能权限（配置授权/操作授权）+ 数据权限 + 用户组管理，底层走 BK-IAM。
- 通知：邮件、站内信、微信等，通道由 ESB CMSI 统一配置。
- 开放能力：OpenAPI 完整，生产案例（边锋游戏）通过 webhook + OpenAPI 实现监控告警自动建单、审批通过后自动触发 CD 部署；支持企业微信移动端、API 请求沙箱、第三方 API 接入规范。

### 2.4 局限与风险

- 开源版更新节奏较慢，企业级增强功能（动态审批、加签、值班管理等）在商业衍生版。
- 部署门槛高（整套蓝鲸基础平台），社区用户反馈安装复杂——这是自研产品可以反超的体验点。

## 三、其他中文开源工单/ITSM 项目

### 3.1 heidsoft/itsm（AI-Native ITSM，个人主导新项目）

- **仓库**：https://github.com/heidsoft/itsm 。定位「对标 ServiceNow 核心能力、轻量私有化、本土集成」。
- **技术栈**：Go 后端 + Next.js 前端 + PostgreSQL（含 pgvector 支撑 RAG）+ Redis + BPMN 工作流引擎；Docker Compose 一键部署。
- **已覆盖能力**（据其 README，未经实测验证）：
  - ITIL 流程：工单、事件、问题、变更（风险评估/多级审批/回滚方案）、发布（发布计划/阶段控制）、服务请求、服务目录、SLA；
  - CMDB：CI 类型、配置项、关系、拓扑、影响分析、云资源发现基础能力；
  - 工作流：BPMN 流程定义、流程实例、用户任务、流程绑定、流程触发；
  - AI：智能分诊（LLM 优先、低置信度降级关键词兜底）、摘要、RAG 检索、LLM 网关、AI 审计（建议可追踪、高风险动作不自动执行）；
  - 知识库：文章/分类/搜索/推荐/RAG 接入；权限：RBAC + 多租户 + MSP 模式；
  - 集成：连接器市场雏形（飞书、钉钉、企微、Webhook）。
- **借鉴点**：AI 深度嵌入（分诊/摘要/审计）而非外挂聊天框的设计哲学；标准变更模板、seed 初始化模板（账号申请、软件安装、网络接入等服务目录模板）的「开箱即用」思路。
- **风险**：个人项目、未经验证，社区与生产案例缺失，仅作方向参考，不作代码依据。

### 3.2 FeelDesk（OS 开源版 / DEV 开发者版 / PRO 专业版）

- **仓库**：https://github.com/feelec-yishu/feeldesk-os 、https://gitee.com/feelecs/feeldesk-dev-base 。商业开源模式（开源版免费、专业版付费），PHP（ThinkPHP 3.2.3/6/8）+ MySQL + Redis，开源版前端 Layui、专业版 Vue + UniApp 移动端。
- **功能细节**：
  - 工单体系：模板类型 → 工单模板（自定义表单组件：单选、多文本、下拉、时间等）→ 工单状态（初始/结束状态必填，中间状态自定义）→ 不同模板绑定不同**路由规则**（按渠道来源、导航菜单、忙闲状态智能分派到组/人；指定处理人时必须在线才能接单）；
  - 字段级权限：不同角色对字段的查看/编辑权限可分别设定；
  - 触发器/自动化：批量处理、批量派单、计划工单，自动完成分配、提醒、转派、变更；
  - SLA：按人/服务目录/优先级自定义指标，以工单发布时间为基线对「开始响应、解决完成」两个维度计时提醒；支持客户工作日个性化、企业营业时间分段、客服弹性工时——**SLA 计时排除非工作时段**的设计非常实用；
  - 协作：处理人/抄送人/协同客服组/外援多角色；子工单必须完结母工单才能关闭；
  - 派单上门：服务商/工程师体系，服务区域+类目匹配派单，APP 接单/抢单、GPS 签到、现场签名确认；
  - 通知：短信、微信、邮件、钉钉；统计：按响应速度、处理速度、SLA 达标率、满意度多维分析。
- **借鉴点**：路由规则的工程化设计、SLA 营业时段日历、字段级权限。注意其本质是客服工单而非 ITIL ITSM，无变更/问题管理。

### 3.3 背景补充：国际开源工单系统（仅列参考坐标）

osTicket（GPL-2.0，邮件转工单经典）、Zammad（AGPL-3.0，多渠道整合+报表）、UVdesk（OSL-3.0，电商集成）、FreeScout（轻量邮箱式）。另 NocoBase（AGPL-3.0，国产低代码平台）可用无代码方式搭工单系统——可作为「自研产品的低代码表单/流程配置能力」的参照。

## 四、Snipe-IT 开源资产管理（可借鉴点）

- **仓库**：github.com/snipe/snipe-it ，**AGPL-3.0**，PHP + Laravel + MySQL，自托管免费；官网 https://snipeitapp.com/product 。
- **核心对象模型**：资产（Asset）、配件（Accessory）、组件（Component）、消耗品（Consumable）、软件许可（License，含席位管理与到期告警）、预定义套件（Kit，批量出库）。资产模型（Asset Model）聚合同类资产的公共属性；状态标签区分「已部署/待部署（待装软件、维修中）/可部署/归档（丢失、损坏）」。
- **关键机制**：
  - **Check-out / Check-in 工作流**：资产指派到人/位置/其他资产，一键归还；出库可要求**用户签署 EULA/接受条款、支持数字签名**；
  - **全量历史**：每个资产保留完整出入库、维修记录与审计日志（操作人+时间戳），支持定期实物盘点（Auditing）；
  - 条码/二维码：生成 QR 标签，手机扫码直达资产页；
  - 自定义字段、CSV 导入导出、预置「可请求（requestable）」资产供用户自助申领；
  - 通知矩阵：用户侧（出入库确认、应归还日期临近提醒）；管理员侧（预期归还报告、许可证到期报告、低库存报告、临近审计提醒）；Slack 集成；
  - 集成与身份：完整 JSON REST API、LDAP/AD 同步、SAML、SCIM 自动开户、Jamf/Kandji（MDM）对接脚本、Jira 插件（工单内查看/编辑资产）；
  - 运维：一键/定时备份、2FA、bcrypt、55+ 语言、按用户语言。
- **已知短板**：无网络自动发现（需手工/导入/脚本）、报表能力弱、无原生移动 App、开箱集成少（靠 API 自建）。
- **对自研 ITSM 的借鉴点**：资产管理模块可直接参照其「对象六分类 + 出入库流 + 状态机 + 审计日志 + EULA 签收」模型；其 Jira 集成模式（在工单详情页内嵌资产面板）正是 ITSM 工单关联资产/CI 的交互蓝本；许可证席位到期告警可并入 SLA/通知中心。若自研产品计划与 Snipe-IT 集成而非自建资产模块，其 REST API 足够支撑双向同步。

## 五、对自研 ITSM（对标 ServiceDesk Plus）的综合建议

| 能力域 | 首选参照 | 关键借鉴点 |
|---|---|---|
| 流程引擎 | bk-itsm | 节点类型体系（人工/审批/会签/自动/子流程/判断）、8 种处理人来源、驳回/回退/转单语义 |
| 自动化规则 | bk-itsm 触发器 + FeelDesk | 事件-条件-动作三段式；RESTful 回调带工单变量；触发记录可审计 |
| SLA | bk-itsm（SLA/OLA 分层）+ FeelDesk（营业时段日历） | 响应/解决双计时、非工作时段排除、多级提醒 |
| 服务目录/门户 | bk-itsm + heidsoft/itsm seed 模板 | 目录-服务项-请求三级；内置常见请求模板开箱即用 |
| 资产/CMDB | Snipe-IT | 六类对象模型、出入库+签收+审计、QR 盘点；工单内嵌资产面板 |
| AI 能力 | heidsoft/itsm | LLM 优先分诊、低置信度降级、AI 审计留痕 |
| 集成架构 | bk-itsm 的解耦思路 | 不自建自动化执行，走 OpenAPI/Webhook 对接外部平台与 IM |

**风险提示**：bk-itsm（MIT）、heidsoft/itsm、FeelDesk OS 协议宽松可自由参考；Snipe-IT 为 AGPL-3.0，若直接嵌入代码有传染性风险，建议仅作功能参照或经 API 集成。
